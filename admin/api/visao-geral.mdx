Endpoints de saúde do serviço, identidade e a visão consolidada que abre o painel. Quase todos aceitam **JWT Bearer ou API Key read-only** (coluna Auth = JWT/Key). Veja [Autenticação](/admin/autenticacao).

<Note>
A URL base `https://admin-api.pujante.com.br` usada nos exemplos é **ilustrativa** — a base real depende do deploy no Railway.
</Note>

<Note>
O parâmetro `origin` aparece em vários endpoints e filtra por produto: `site` (AgroPujante), `escola` ou `all` (default na maioria) — veja [Convenções](/admin/convencoes#parametro-origin).
</Note>

## Erros comuns

Os shapes 401/403/422 são os padrões da API — veja [Convenções](/admin/convencoes#erros-comuns). Os exemplos por endpoint referenciam essa página em vez de repeti-los.

## Health

| Método | Path | Descrição | Auth |
|---|---|---|---|
| GET | `/health` | Health check básico | Nenhuma |
| GET | `/health/deep` | Health profundo: valida JWKS e estado das MVs | Nenhuma |

<AccordionGroup>
<Accordion title="GET /health">
```bash title="Requisição (sem auth)"
curl "https://admin-api.pujante.com.br/health"
```

```json title="200 OK"
{
  "status": "ok",
  "ts": "2026-06-12T14:03:21.482910+00:00"
}
```
</Accordion>

<Accordion title="GET /health/deep">
```bash title="Requisição (sem auth)"
curl "https://admin-api.pujante.com.br/health/deep"
```

```json title="200 OK"
{
  "status": "ok",
  "checks": { "jwks": true, "mvs": true, "mvs_count": 9 },
  "ts": "2026-06-12T14:03:24.118273+00:00"
}
```

Se o JWKS estiver inacessível ou as MVs não puderem ser listadas, `status` vira `"degraded"` (a resposta continua **200**):

```json title="200 OK — degradado"
{
  "status": "degraded",
  "checks": { "jwks": false, "mvs": true, "mvs_count": 9 },
  "ts": "2026-06-12T14:03:24.118273+00:00"
}
```
</Accordion>
</AccordionGroup>

## Me

| Método | Path | Descrição | Auth |
|---|---|---|---|
| GET | `/me` | Dados do usuário autenticado (`sub`, `email`, `role`) | JWT/Key |

<AccordionGroup>
<Accordion title="GET /me">
```bash title="Requisição (JWT)"
curl "https://admin-api.pujante.com.br/me" \
  -H "Authorization: Bearer <TOKEN>"
```

```bash title="Requisição (API key)"
curl "https://admin-api.pujante.com.br/me" \
  -H "X-API-Key: <API_KEY>"
```

```json title="200 OK — via JWT"
{
  "sub": "8d4c2a1e-7f3b-4e9a-b6d5-1c2e3f4a5b6c",
  "email": "pedro@pujante.com.br",
  "role": "authenticated"
}
```

Via API key, o principal é sintético (prefixo `api_key:` + id da chave):

```json title="200 OK — via API key"
{
  "sub": "api_key:f3a9c1d2-5e6b-4a7c-8d9e-0f1a2b3c4d5e",
  "email": "api_key:f3a9c1d2-5e6b-4a7c-8d9e-0f1a2b3c4d5e",
  "role": "api_key"
}
```

Erros 401/403: veja [Erros comuns](/admin/convencoes#erros-comuns).
</Accordion>
</AccordionGroup>

## Materialized views

<Tip>
A lista completa de MVs (o que cada uma agrega, fontes e staleness) está documentada em [Arquitetura](/admin/arquitetura#catalogo-das-mvs).
</Tip>

| Método | Path | Descrição | Auth |
|---|---|---|---|
| GET | `/admin/mvs` | Lista MVs `admin_mv_*` e status de refresh | JWT/Key |
| POST | `/admin/mvs/refresh` | Força refresh (`?concurrent=true` para não travar leituras) | JWT/Key |

<AccordionGroup>
<Accordion title="GET /admin/mvs">
```bash title="Requisição (JWT)"
curl "https://admin-api.pujante.com.br/admin/mvs" \
  -H "Authorization: Bearer <TOKEN>"
```

```bash title="Requisição (API key)"
curl "https://admin-api.pujante.com.br/admin/mvs" \
  -H "X-API-Key: <API_KEY>"
```

```json title="200 OK"
{
  "count": 2,
  "views": [
    {
      "name": "admin_mv_kpis_monthly",
      "is_populated": true,
      "size_bytes": 245760,
      "refreshed_at": "2026-06-12T03:00:04+00:00"
    },
    {
      "name": "admin_mv_subscribers",
      "is_populated": true,
      "size_bytes": 1048576,
      "refreshed_at": "2026-06-12T03:00:09+00:00"
    }
  ]
}
```

Erros 401/403: veja [Erros comuns](/admin/convencoes#erros-comuns).
</Accordion>

<Accordion title="POST /admin/mvs/refresh">
Escrita: **somente JWT**. Uma API key recebe **403** (veja [Erros comuns](/admin/convencoes#erros-comuns)).

```bash title="Requisição (JWT)"
curl -X POST "https://admin-api.pujante.com.br/admin/mvs/refresh?concurrent=true" \
  -H "Authorization: Bearer <TOKEN>"
```

```json title="200 OK"
{
  "count": 2,
  "results": [
    { "name": "admin_mv_kpis_monthly", "status": "ok", "error": null },
    { "name": "admin_mv_subscribers", "status": "ok", "error": null }
  ]
}
```

Falhas de refresh em uma MV não derrubam a chamada — vêm linha a linha em `results` com `status != "ok"` e o `error` preenchido.
</Accordion>
</AccordionGroup>
