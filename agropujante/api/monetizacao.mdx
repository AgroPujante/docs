## Erros comuns

O handler global adiciona `code` ao body. Shapes que se repetem:

```json title="401 Unauthorized — sem credencial"
{ "detail": "Token de autenticação não fornecido", "code": "http_error" }
```

```json title="401 Unauthorized — token ruim"
{ "detail": "Token inválido ou expirado", "code": "http_error" }
```

```json title="403 Forbidden — role insuficiente (endpoints admin+)"
{ "detail": "Acesso negado — permissão insuficiente", "code": "http_error" }
```

```json title="422 Unprocessable Entity — validação Pydantic (shape padrão FastAPI)"
{
  "detail": [
    {
      "type": "literal_error",
      "loc": ["body", "billing_type"],
      "msg": "Input should be 'PIX' or 'CREDIT_CARD'",
      "input": "BOLETO"
    }
  ]
}
```

## Subscriptions (`/subscriptions`)

| Método | Path | Descrição | Auth |
|---|---|---|---|
| GET | `/subscriptions/plans` | Planos PRO — mensal, trimestral, anual (com desconto) | Público |
| POST | `/subscriptions/checkout` | Cria checkout no Asaas (PIX/cartão) | JWT |
| POST | `/subscriptions/webhook` | Webhook Asaas — valida header `asaas-access-token` | Público (token) |
| POST | `/subscriptions/cancel` | Cancela a assinatura | JWT |

<Accordion title="POST /api/v1/subscriptions/checkout">
Exige CPF/CNPJ no perfil. Retorna a URL da página de pagamento do Asaas.

```bash title="Requisição"
curl -X POST "https://api.agropujante.com.br/api/v1/subscriptions/checkout" \
  -H "Authorization: Bearer <TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{"plan": "annual"}'
```

```json title="200 OK"
{
  "checkout_url": "https://www.asaas.com/c/abc123def456",
  "subscription_id": "sub_000012345678"
}
```

```json title="400 Bad Request — plano inválido"
{ "detail": "Plano inválido: trimestral. Opções: monthly, semiannual, annual", "code": "http_error" }
```

```json title="400 Bad Request — já assinante"
{ "detail": "Você já possui uma assinatura ativa", "code": "http_error" }
```

```json title="400 Bad Request — sem CPF/CNPJ"
{ "detail": "CPF/CNPJ é obrigatório para assinar. Atualize seu perfil.", "code": "http_error" }
```
</Accordion>

<Accordion title="POST /api/v1/subscriptions/webhook">
Webhook do Asaas — valida o header `asaas-access-token`. Sempre responde 200 com `{"received": true}` após aceitar o evento (mesmo se o processamento interno falhar, para evitar retries do Asaas).

```bash title="Requisição (payload enviado pelo Asaas)"
curl -X POST "https://api.agropujante.com.br/api/v1/subscriptions/webhook" \
  -H "asaas-access-token: <TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{
    "event": "PAYMENT_CONFIRMED",
    "payment": {
      "id": "pay_080225913252",
      "customer": "cus_000005219613",
      "subscription": "sub_000012345678",
      "value": 118.80,
      "billingType": "PIX",
      "status": "CONFIRMED",
      "externalReference": "9a1d4f22-3b5c-4e7d-8f90-1a2b3c4d5e6f"
    }
  }'
```

```json title="200 OK"
{ "received": true }
```

```json title="401 Unauthorized — token do webhook errado"
{ "detail": "Invalid webhook token", "code": "http_error" }
```

```json title="400 Bad Request — sem event"
{ "detail": "Missing event type", "code": "http_error" }
```
</Accordion>

<Accordion title="POST /api/v1/subscriptions/cancel">
```bash title="Requisição"
curl -X POST "https://api.agropujante.com.br/api/v1/subscriptions/cancel" \
  -H "Authorization: Bearer <TOKEN>"
```

```json title="200 OK"
{
  "success": true,
  "message": "Assinatura cancelada com sucesso. Você ainda terá acesso até o final do período pago."
}
```

```json title="400 Bad Request — nada pra cancelar"
{ "detail": "Você não possui uma assinatura ativa para cancelar", "code": "http_error" }
```
</Accordion>
</AccordionGroup>

Pagamento confirmado → `site_subscriptions.status = active` + `users.is_subscriber = true` + evento em `site_subscription_events`. Fluxo completo em [Trial → PRO](/agropujante/fluxos#trial-pro).

## Supporter checkout (`/supporter-checkout`)

| Método | Path | Descrição | Auth |
|---|---|---|---|
| GET | `/supporter-checkout/plans` | Planos de apoiador/escritório | Público |
| POST | `/supporter-checkout/checkout` | Checkout PIX ou CREDIT_CARD | JWT |
| GET | `/supporter-checkout/status` | O usuário é apoiador? | JWT |
| GET | `/supporter-checkout/upgrade-preview` | Opções de upgrade para PRO | JWT |

<Warning>
Apoiador e PRO **não coexistem** (1 assinatura por usuário). Supporter ativo já carrega acesso PRO via `users.is_subscriber` — não crie uma segunda assinatura.
</Warning>

<Accordion title="POST /api/v1/supporter-checkout/start">
PIX (pagamento avulso do 1º ciclo) ou CREDIT_CARD (recorrente, exige `payment_method_id` de cartão tokenizado). Se o user tem PRO ativa, ela é cancelada **antes** de criar a supporter (evita cobrança dupla).

```bash title="Requisição — PIX"
curl -X POST "https://api.agropujante.com.br/api/v1/supporter-checkout/start" \
  -H "Authorization: Bearer <TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{
    "plan": "supporter-monthly",
    "billing_type": "PIX",
    "cpf_cnpj": "12345678000190"
  }'
```

  "payment_id": "pay_080225913252",
  "status": "pending",

    "copy_paste": "00020126580014br.gov.bcb.pix...",
    "expiration_date": "2026-06-13 23:59:59"

## Cartões e checkout v2 (`/checkout`)

| Método | Path | Descrição | Auth |
|---|---|---|---|
| POST | `/checkout/cards` | Tokeniza cartão no Asaas (PAN nunca é persistido) | JWT |

## Credits (`/credits`)

Saldo de gamificação do usuário.

| Método | Path | Descrição | Auth |
|---|---|---|---|
| GET | `/credits/balance` | Saldo atual | JWT |
| GET | `/credits/history` | Histórico de eventos de crédito | JWT |
| GET | `/credits/streak` | Streak atual e chaves de revive | JWT |
| POST | `/credits/check-in` | Check-in diário | JWT |
| POST | `/credits/track-share` | Crédito por compartilhamento | JWT |
| POST | `/credits/track-read` | Crédito por leitura | JWT |
| POST | `/credits/claim-welcome-gift` | Resgata bônus de boas-vindas | JWT |
| POST | `/credits/redemption/preview` | Preview de resgate | JWT |

<Note>
Não há endpoint genérico de escrita: earn/spend/refund rodam só via hooks internos. As escritas expostas são tasks específicas — `POST /credits/track-share` e `POST /credits/track-read` (além de `/credits/check-in` e `/credits/claim-welcome-gift`).
</Note>

<Accordion title="POST /api/v1/credits/track-share">
Credita coin por compartilhar um post (idempotente por user+post; cap 1/dia).

```bash title="Requisição"
curl -X POST "https://api.agropujante.com.br/api/v1/credits/track-share" \
  -H "Authorization: Bearer <TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{"post_id": "c2d3e4f5-6a7b-4c8d-9e0f-1a2b3c4d5e6f"}'
```

```json title="200 OK — creditado"
{ "credited": true, "balance": 86, "task_code": "share_post", "amount": 1, "reason": null }
```

```json title="200 OK — duplicado (não é erro)"
{ "credited": false, "balance": 86, "task_code": "share_post", "amount": null, "reason": "idempotent_duplicate" }
```

`reason`: `task_not_found_or_inactive` | `already_credited_one_shot` | `daily_limit_reached` | `idempotent_duplicate`.
</Accordion>

<Accordion title="POST /api/v1/credits/track-read">
Credita coin por leitura completa de artigo (idempotente por user+post; cap 5/dia). O frontend valida a leitura (scroll + tempo) antes de chamar.

```bash title="Requisição"
curl -X POST "https://api.agropujante.com.br/api/v1/credits/track-read" \
  -H "Authorization: Bearer <TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{"post_id": "c2d3e4f5-6a7b-4c8d-9e0f-1a2b3c4d5e6f"}'
```

```json title="200 OK"
{ "credited": true, "balance": 87, "task_code": "read_article", "amount": 1, "reason": null }
```
</Accordion>
</AccordionGroup>

## Supporter leads (`/supporter-leads`)

| Método | Path | Descrição | Auth |
|---|---|---|---|
| POST | `/supporter-leads` | Formulário de lead (name, email, office, phone, message) | Público |
| GET | `/supporter-leads` | Lista leads | admin+ |
| GET | `/supporter-leads/unread-count` | Contagem de leads não lidos | admin+ |
| PATCH | `/supporter-leads/{lead_id}/read` | Marca lead como lido | admin+ |
| PATCH | `/supporter-leads/read-all` | Marca todos como lidos | admin+ |
