Base: `/api/v1`. Roles: ver [Autenticação](/agropujante/autenticacao).

## Erros comuns

Shapes de erro (`{detail, code}`), 422 do Pydantic e 429 do slowapi seguem as [convenções da API](/agropujante/convencoes). Específico desta página: um detalhe de mensagem — o 401 sem credencial diz `"Não autenticado"` nos endpoints admin e `"Token de autenticação não fornecido"` no pipeline `/users`. Vários endpoints aqui têm rate limit próprio (indicado em cada accordion).

## Auth (`/auth`)

| Método | Path | Descrição | Auth |
|---|---|---|---|
| POST | `/auth/login` | Email/senha → `{access_token, refresh_token, user}` | Público |
| POST | `/auth/refresh` | Renova o par de tokens | Público |
| POST | `/auth/logout` | Invalida a sessão | JWT |
| GET | `/auth/me` | Usuário atual | JWT |

<AccordionGroup>
<Accordion title="POST /api/v1/auth/login">
Rate limit: `10/minute`.

```bash title="Requisição"
curl -X POST "https://api.agropujante.com.br/api/v1/auth/login" \
  -H "Content-Type: application/json" \
  -d '{"email": "ana.carvalho@exemplo.com.br", "password": "S3nhaForte1"}'
```

```json title="200 OK"
{
  "access_token": "<TOKEN>",
  "refresh_token": "<TOKEN>",
  "token_type": "bearer",
  "user": {
    "id": "7f3b2c10-9d4e-4a8b-b1c2-5e6f7a8b9c0d",
    "email": "ana.carvalho@exemplo.com.br",
    "app_role": "editor"
  }
}
```

Erros genéricos (422, 429): ver [convenções da API](/agropujante/convencoes).
</Accordion>

<Accordion title="POST /api/v1/auth/refresh">
Rate limit: `30/minute`. O Supabase rotaciona o refresh token a cada chamada — sempre persista o novo par.

```bash title="Requisição"
curl -X POST "https://api.agropujante.com.br/api/v1/auth/refresh" \
  -H "Content-Type: application/json" \
  -d '{"refresh_token": "<TOKEN>"}'
```

```json title="200 OK"
{
  "access_token": "<TOKEN>",
  "refresh_token": "<TOKEN>",
  "token_type": "bearer"
}
```

```json title="401 Unauthorized"
{ "detail": "Refresh token inválido ou expirado", "code": "http_error" }
```
</Accordion>

<Accordion title="POST /api/v1/auth/logout">
```bash title="Requisição"
curl -X POST "https://api.agropujante.com.br/api/v1/auth/logout" \
  -H "Authorization: Bearer <TOKEN>"
```

```text title="204 No Content"
(sem body)
```

Erros genéricos (401): ver [convenções da API](/agropujante/convencoes).
</Accordion>

## Users (`/users`)

| Método | Path | Descrição | Auth |
|---|---|---|---|
| POST | `/users/register` | Registro de conta | Público |
| POST | `/users/login` | Login alternativo | Público |
| POST | `/users/google-login` | OAuth Google | Público |
| GET | `/users/me` | Perfil do usuário logado | JWT |
| PATCH | `/users/me` | Atualiza dados do perfil | JWT |
| GET | `/users/access-check` | Checa acesso a conteúdo gated (paywall) | JWT |
| POST | `/users/track-read` | Registra leitura de post | JWT |
| GET | `/users/me/saved-posts` | Posts salvos | JWT |
| POST | `/users/me/saved-posts/{post_id}` | Salva um post | JWT |
| DELETE | `/users/me/saved-posts/{post_id}` | Remove dos salvos | JWT |

<Warning>
Antes de depurar falha de login de **apoiador**, leia o [gotcha dos 2 pipelines](/agropujante/autenticacao#gotcha-os-2-pipelines-de-auth-de-apoiador): contas com `password_hash = 'supabase_managed'` não logam por senha do portal.
</Warning>

<Note>
O bloco `escola` no payload de `UserPublic` (`has_access`, `user_type`, `role`, `subscription_active`) reflete a situação do usuário na **Escola Pujante** — é a base do handoff entre os produtos. A auth do lado da Escola está em [Escola: API de auth](/escola/api/auth); a visão geral da integração, em [Ecossistema](/ecossistema).
</Note>

<AccordionGroup>
<Accordion title="GET /api/v1/profiles/handle-available">
Bearer opcional — se o handle pertence ao próprio user logado, retorna `available: true` (permite re-salvar o mesmo handle no formulário).

## Password reset (`/password-reset`)

| Método | Path | Descrição | Auth |
|---|---|---|---|
| POST | `/password-reset/request` | Envia OTP de 6 dígitos por email | Público |
| POST | `/password-reset/verify` | Valida o OTP (máx. 3 tentativas) | Público |
| POST | `/password-reset/confirm` | Define a nova senha | Público |

<AccordionGroup>
<Accordion title="POST /api/v1/users/password-reset/request">
Rate limit: `10/hour` por IP + máx. 3 códigos por email/hora. A resposta é **sempre** a mesma (200 genérico) — o endpoint não revela se a conta existe.

```bash title="Requisição"
curl -X POST "https://api.agropujante.com.br/api/v1/users/password-reset/request" \
  -H "Content-Type: application/json" \
  -d '{"email": "ana.carvalho@exemplo.com.br"}'
```

```json title="200 OK"
{ "message": "Se esse email estiver cadastrado, enviamos um código de verificação." }
```

Erros genéricos (422, 429): ver [convenções da API](/agropujante/convencoes).
</Accordion>

<Accordion title="POST /api/v1/users/password-reset/verify">
Rate limit: `30/hour`. O código tem 6 dígitos, vale por 10 minutos e admite no máx. 5 tentativas erradas.

```bash title="Requisição"
curl -X POST "https://api.agropujante.com.br/api/v1/users/password-reset/verify" \
  -H "Content-Type: application/json" \
  -d '{"email": "ana.carvalho@exemplo.com.br", "code": "482913"}'
```

```json title="200 OK"
{ "reset_token": "<TOKEN>" }
```

O `reset_token` é um JWT de curta duração (5 min) que autoriza só o `/confirm`.

```json title="400 Bad Request — código errado/expirado"
{ "detail": "Código inválido ou expirado.", "code": "http_error" }
```

```json title="429 Too Many Requests — 5 tentativas erradas"
{ "detail": "Muitas tentativas. Solicite um novo código.", "code": "http_error" }
```
</Accordion>

<Accordion title="POST /api/v1/users/password-reset/confirm">
Rate limit: `30/hour`. Senha mínima: 8 caracteres com letras e números.

```bash title="Requisição"
curl -X POST "https://api.agropujante.com.br/api/v1/users/password-reset/confirm" \
  -H "Content-Type: application/json" \
  -d '{"reset_token": "<TOKEN>", "new_password": "NovaSenha2026"}'
```

```json title="200 OK"
{ "message": "Senha redefinida com sucesso." }
```

```json title="401 Unauthorized — reset_token vencido"
{ "detail": "Sessão de redefinição expirou. Solicite um novo código.", "code": "http_error" }
```

```json title="400 Bad Request — senha fraca"
{ "detail": "A senha precisa ter no mínimo 8 caracteres, incluindo letras e números.", "code": "http_error" }
```
</Accordion>
</AccordionGroup>

<Note>
O reset cobre apenas o pipeline Supabase Auth ou o portal-nativo correspondente à conta — resetar em um mundo não destrava o outro.
</Note>
